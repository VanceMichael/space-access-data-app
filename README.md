# 青年服务空间的试辟点位与覆盖证据

业务资料均为合成记录。表头字段及跨表引用见 `fixtures/format.json`。

## 数据说明

请求的 needed 列按登记顺序，same 意味着只能同点办理，split 仍要留出足够行走时间。时间窗均半开，minutes 为完整办理用时。journeys 是点位与片区之间可观察的方向行程，未提供方向不默认可达。当晚场次在表里同时包含基准及候选用到的记录，候选与受影响点当前开放表合并比较，重复出现同场次仍只有一份容量。
转介状态 completed 仅作覆盖事实，notified 仍需预留至办理结果或经办确认更改。需求调查权重不是实际可找某个地址的联系量。资源同一时刻可开的场次取 available-resources，预算及公开样本线取 limits。

CSV 使用 UTF-8、逗号分隔，无引号与内嵌换行。未提供的字段是空字符串，作为关系值的 `-` 表示不适用。多值字段用竖线分隔，数值和日期单位见业务约定。

## 评审数据应用

依赖仅为 Node.js 标准库，代码在 `tools/lib/`：

| 模块 | 职责 |
| --- | --- |
| `csv.mjs` / `time.mjs` | CSV 解析（兼容 CRLF）；时间换算为相对 18:00 的分钟数，半开窗口与 18 点前后两档行程耗时 |
| `loader.mjs` | 读表、应用街道开放变更；被转介引用的场次标记为基准排期，其余为候选，未购买前不开放 |
| `feasibility.mjs` | 需求可达性搜索：same 锁定同点连办、split 按事项顺序拆点并留行程；资源并发冲突检测；三档交通情景 |
| `plan.mjs` | 席位分配（按接待条数，weight 仅用于加权）、方案合并去重、冲突让位模拟 |
| `stats.mjs` | 分区加权可达/覆盖率、有效样本量 n_eff、小样本与可识别风险抑制、交通敏感性翻转 |
| `referrals.mjs` | 转介台账：区分「转介未办成」与「尚无人申请」，通知不假定收回 |
| `intake.mjs` | 街道周度开放变更与已办反馈接收，输出场次去留与证据强度（强/弱） |
| `report.mjs` | 装配内部审议报告与公开摘要，含同距不同覆盖的解释链 |

### 运行

```bash
npm ci --ignore-scripts --offline   # 准备工作区
npm run check:materials             # 字段与跨表引用检查
npm test                            # 资料检查 + 25 项业务规则测试
npm run review                      # 生成 dist/internal-review.json 与 dist/public-summary.json
npm run weekly                      # 处理 examples/weekly 下的下周变更与已办反馈
```

也可指定目录：`node tools/review.mjs <数据目录> <输出目录>`；
`node tools/weekly.mjs <数据目录> <变更csv|-> <反馈csv|-> <输出目录>`。

## 口径要点（评审可追溯）

1. **需求按能实际办完的服务组合度量**。same 组合不拆成多次覆盖，找不到同点齐备的开放点位即不可达；split 组合按 needed 顺序逐场搜索，两点之间必须有可观察方向行程并计入耗时。
2. **两层口径分开**：可达（reachable）只看时间、行程、开放时段；覆盖（covered）还要在场次 slots 内排到席位。slots 按接待条数计，`weight` 是抽样权重，只用于加权估计，不参与席位扣减。
3. **停用与时段调整**：`changes` 的 closed 移除点位当天全部场次，open 按上报区间与场次窗口取交集，容不下完整办理用时即不可办。
4. **转介不等于需求**：分区比较的是全部匿名需求的可达与缺口；`review.result=unfinished` 与「尚无人申请」分别建账，notified 未办结的承诺持续挂账。
5. **抽样与披露**：每区报告有效样本量 `(Σw)²/Σw²` 与单条权重占比；低于 `disclosure_min_people` 或估计由极少数回答支撑时，公开摘要只给方向性表述，数值仅进内部审议。
6. **同距不同覆盖可解释**：`explanations` 给出每条结论的通道方向、18 点前后耗时差、到场/办结时刻与窗口约束；交通假设按 -10%/观察/+10% 三档复算，翻转的需求标记为不稳健。
7. **方案比较三件套**：总体覆盖增长、最薄弱片区是否改善、让位模拟挤掉的基准可办机会（需求级与权重）。资源同一时刻重叠场次数超过 `concurrent_capacity` 即冲突，不做静默删场。
8. **预算与底线冲突不假装解决**：所有两两组合均超预算时列明超支额；没有方案同时满足片区底线与转介承诺时，给出冲突清单与替代安排，不假定通知已收回。
9. **隐私边界**：任何输出不使用精确住址解释点位取舍；公开摘要不含匿名需求记录号、个案行程与地址字段。

## 当前数据的主要结论（合成示例）

- 基准排期仅 S3、S4 有效（P1 装修停用，候选 S5/S6 未购买）：加权可达率 31.9%，A 区 38.5%、C 区 19.4% 低于 0.4 保障底线，B 区 40.6% 达标。

- O2 成本 55：新增 advice 晚场 S5，无资源冲突，三个片区全部越过底线，可达权重 +27。

- 两两组合成本 105/110/115，均超 100 预算；R5（C 区）在 tight 情景翻转可达，是唯一对交通假设敏感的需求。
